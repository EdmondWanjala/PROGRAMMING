            APPLICATION DEVELOPMENT
Application development is the process of creating software programs designed to perform specific tasks, solve problems or provide services to users.
An application is a software system that accepts input, processes information, performs operations and produces useful output.
  Main objectives
- Automate tasks and processes.
- Solve practical and business problems.
- Improve productivity and efficiency.
- Process, store and retrieve information.
- Facilitate communication and collaboration.
- Provide user-friendly digital services.
- Integrate hardware, software and network systems.
  Examples of applications
- Calculator applications.
- Banking applications.
- Inventory management systems.
- Educational applications.
- Mobile communication applications.
- Engineering design software.
- Business management systems.
- IoT monitoring applications.
- Industrial automation applications.
- Artificial intelligence applications.

 Application Development Life Cycle (ADLC)
The Application Development Life Cycle describes the stages involved in creating and maintaining an application.
 Stage 1: Problem Identification
Identify the problem the application should solve.
Activities:
- Understand the existing problem.
- Identify users.
- Establish application objectives.
- Determine expected outcomes.
 Stage 2: Requirements Analysis
Determine what the application must do and the conditions under which it must operate.
Functional requirements describe application behavior.
Examples:
- User registration.
- Login.
- Data entry.
- Calculations.
- Report generation.
Non-functional requirements describe quality attributes.
Examples:
- Performance.
- Security.
- Reliability.
- Scalability.
- Usability.
- Maintainability.
 Stage 3: Feasibility Study
Determine whether the proposed application can be developed successfully.
Types:
- Technical feasibility.
- Economic feasibility.
- Operational feasibility.
- Legal feasibility.
- Schedule feasibility.
 Stage 4: System Design
Define how the application will be structured and implemented.
Activities:
- Design application architecture.
- Design user interfaces.
- Design database structures.
- Define application modules.
- Define data flow.
- Select programming languages and frameworks.
 Stage 5: Development
Write the source code and implement the application features.
Activities:
- Build interfaces.
- Implement business logic.
- Develop APIs.
- Connect databases.
- Integrate hardware or external systems.
 Stage 6: Testing
Verify that the application works correctly.
Activities:
- Unit testing.
- Integration testing.
- System testing.
- User acceptance testing.
- Performance testing.
- Security testing.
 Stage 7: Deployment
Make the application available to its intended users.
Examples:
- Installing desktop software.
- Publishing mobile applications.
- Hosting web applications.
- Flashing firmware to embedded devices.
 Stage 8: Maintenance
Maintain and improve the application after deployment.
Activities:
- Bug fixing.
- Security updates.
- Performance improvements.
- Feature additions.
- Compatibility updates.
- Data backup.

Methodologies define how software projects are organized and managed.
  Waterfall Model
A sequential development approach in which each major phase is completed before the next phase begins.
Stages:
1. Requirements.
2. Design.
3. Implementation.
4. Testing.
5. Deployment.
6. Maintenance.

 Application Architecture
Application architecture defines the structure of an application, its components and how they communicate.
  Monolithic architecture
An application is built and deployed as one main software unit.
Advantages:
- Simple initial development.
- Easier deployment for small systems.
- Straightforward communication between internal modules.
Limitations:
- Can become difficult to maintain as the application grows.
- Independent component scaling is limited.
  Layered architecture
Divides an application into logical layers.
Common layers:
1. Presentation layer — user interface.
2. Application or business layer — application operations.
3. Data access layer — communication with storage systems.
4. Database layer — persistent data storage.
  Client-server architecture
The client requests services while the server processes requests and returns responses.
Examples:
- Mobile application communicating with a backend.
- Desktop application accessing a database server.
- Browser accessing a web application.
 Model-View-Controller (MVC)
Separates an application into:
Model: Handles data and business rules.
View: Displays information to users.
Controller: Receives user actions and coordinates application operations.
 Model-View-ViewModel (MVVM)
Separates the interface from presentation logic using a ViewModel.
Commonly used in modern desktop and mobile application development.
  Microservices architecture
Divides an application into smaller independently deployable services.
Advantages:
- Independent deployment.
- Independent scaling.
- Technology flexibility.
Limitations:
- Distributed-system complexity.
- Network communication overhead.
- More demanding monitoring and operations.

 Application Security
Application security protects software, data and users from malicious activity and unauthorized access.
 Common vulnerabilities
Injection attacks: Untrusted input alters commands or database queries.
Cross-Site Scripting: Malicious scripts execute in a user's browser.
Broken authentication: Weaknesses allow unauthorized access to accounts.
Broken access control: Users gain access to unauthorized resources.
Insecure data storage: Sensitive information is exposed through inadequate storage protection.
Insecure communication: Data is transmitted without sufficient protection.
 Security practices
- Validate input.
- Sanitize data where appropriate.
- Use parameterized database queries.
- Hash passwords using Argon2id or bcrypt.
- Encrypt sensitive communications using TLS.
- Implement authentication and authorization.
- Protect application secrets.
- Apply least-privilege permissions.
- Keep dependencies updated.
- Conduct security testing.
- Log security-relevant events.
 Authentication and authorization
Authentication verifies who a user is.
Authorization determines what that user can access or perform.
 Role-Based Access Control (RBAC)
Assigns permissions according to roles.
Example:
- Administrator.
- Manager.
- Employee.
- Customer.
- Viewer.

 Application Architecture Patterns and Design Principles
  Object-Oriented Programming
Organizes software around objects that combine data and behavior.
 Four major principles:
Encapsulation: Combines data and related methods while controlling access.
Abstraction: Exposes essential behavior while hiding unnecessary implementation details.
Inheritance: Allows a class to derive properties and behavior from another class.
Polymorphism: Allows different objects to respond to the same interface in different ways.
  SOLID principles
- Single Responsibility Principle.
- Open/Closed Principle.
- Liskov Substitution Principle.
- Interface Segregation Principle.
- Dependency Inversion Principle.
These principles help create maintainable object-oriented software.
  Design patterns
Common reusable software design solutions:

- Strategy.
- Adapter.
- Repository.
- Dependency Injection.

 Important Application Development Metrics and Formulas
  Availability
Availability = Uptime / (Uptime + Downtime) × 100%
  Test coverage
Test Coverage = (Code Elements Tested / Total Measured Code Elements) × 100%
  Error rate
Error Rate = (Failed Operations / Total Operations) × 100%
  Throughput
Throughput = Completed Operations / Time
  Memory utilization
Memory Utilization = (Memory Used / Total Available Memory) × 100%
  Development cost
Total Development Cost = Development Labour + Infrastructure + Software + Testing + Deployment + Maintenance Costs
